# How Nanogram for Android differs from upstream Telegram for Android

Kept current with every change that alters behaviour or build compared with upstream (DrKLO/Telegram 13.2.2 (7303)).

| Area | Difference | Why |
|---|---|---|
| Repositories | Telegram-specific submodules point at klaipher forks; tgcalls shares `klaipher/tgcalls` with iOS/Mac (one branch for all three apps, `nanogram-shared`; the Android pin moves in the tgcalls integration step); `shared/` = klaipher/nanogram-deps (manifest and checker, same commit as iOS/Mac); media fork branch `nanogram-android` | Control over patches, one tgcalls fork for all apps | Current pin: 7afc0b25.
| Prebuilt libraries | Upstream's committed `TMessagesProj/jni/prebuild/lib/**` and `prebuild/include/**` are deleted on purpose; `ng prebuild` builds everything from source into `~/.cache/nanogram-android/prebuild/<key>`, and CMake fails without `nanogramPrebuildDir`. An upstream sync that re-adds those files (they change on every upstream FFmpeg/BoringSSL bump) must keep them deleted: resolve modify/delete conflicts as delete | 204 MB of binaries per clone, stale ABI-skewed archives that linked silently, one build path |
| Identity | `org.klaipher.nanogram`, app name Nanogram, own api_id/api_hash via BuildConfig, own release key, own Firebase config only | Separate app; no Telegram credentials or Firebase project |
| Fork flags | `IS_BILLING_UNAVAILABLE = true`, `SUPPORTS_PASSKEYS = false`, empty Play Store URL | Play billing and passkeys only work for Telegram's app ids |
| ABIs | arm64-v8a only by default (`-PnanogramAbis=all` for all four) | Speed and size; like Apple-Silicon-only on the Mac |
| versionCode | minutes since 2020-01-01 of the build number × 10 + ABI digit | Every build updates the previous one; marketing version follows upstream |
| Toolchain | Gradle 9.9, AGP 9.5, Kotlin 2.4, NDK r30, CMake 4.1, compileSdk 37, Java 17 | Current toolchain; targetSdk 36 unchanged (minSdk: see its row) |
| Native build | native API level 31 for CMake and every prebuild (cache key changes), RELR packed relocations, ccache, no LTO in debug, prebuilts rebuilt from submodules into a cache, 16 KB flexible page sizes, uncompressed native libs | Build speed, disk, device storage, 16 KB-page devices |
| Native deps | FFmpeg 9.0.2 (n9.0.2, same as iOS and macOS); TDLib = iOS pin 0e88653d (1.8.69); abseil 20260817.0; BoringSSL 0.20261105.0; OpenH264 2.7.0; boost-regex 1.92.0 | Latest releases; one TDLib for iOS and Android |
| Gradle modules | 11 of 40 media modules; Huawei/HockeyApp/Standalone/test apps only with `-Pnanogram.allModules=true` | Configuration time |
| Biometrics | No FingerprintManager (removed from SDK 37): `androidx.biometric` 1.1.0 everywhere (FingerprintManagerCompat copy deleted); wallet uses the framework BiometricPrompt only (AndroidX prompt path removed with minSdk 31); face/iris accepted where the device rates them Class 3 | Newer API on compileSdk 37, no stubs |
| Own-code fallbacks (minSdk 31) | Pre-31 branches removed in Nanogram-owned code only: `NanogramUpdater` (signing certificates, long version code, install-permission and user-action flags), `NanogramDiagnostics`, `NanogramSystemInfo` (install source, WebView, SoC, thermal, standby bucket, exact alarms, signing certificate), `NanogramStrictMode`, `NanogramFrameStats`, `NanogramExitInfo` (no `isSupported`), `GramWalletStorageAuth` (AndroidX biometric prompt and API 23/30 guards). Upstream files keep their `SDK_INT` checks | No dead compat code in our files; upstream merges stay clean |
| WebRTC source | klaipher/webrtc `nanogram` (fa0b3c5f) as submodule `jni/voip/webrtc`, the same commit iOS and macOS pin; replaces the 4,267-file in-tree copy (`jni/voip/webrtc`) and the Java copy `src/main/java/org/webrtc` (Gradle `srcDirs` now point into the submodule; `EglThread.java`, the one extra upstream class in those directories, is excluded because it cannot compile against the Telegram `EglBase`). Android gains the 12 WebRTC security/crash fixes, keeps the legacy audio device, screen-share audio, iSAC and the Telegram-modified `org.webrtc` Java (the edits live in the fork, 173 of 173 old Java files blob-identical, 4,090 of 4,267 C++ files identical, the rest ledgered), and the `Candidate::set_type` change is in the fork already (api/candidate.h is blob-identical to the old Android copy) | One WebRTC for all Nanogram apps; the Android-only parts live in the fork under `WEBRTC_ANDROID`. Only debug-counter edits (FileLog) are dropped, because the fork cannot call tgnet |
| WebRTC dependencies | abseil 20260817.0, libsrtp v2.5.0 and crc32c 21fc8ef3 are the fork's nested submodules (shallow); pffft, rnnoise-vad (Chromium `third_party/rnnoise`), jni_zero come from the fork's `third_party/`; usrsctp and libevent are gone (nothing used usrsctp; the task queue is the stdlib one); `jni/third_party/absl`, `libsrtp`, `usrsctplib`, `pffft`, `rnnoise` and `jni/voip/third_party` are deleted | One source per library; libsrtp moves 2.2.0 to 2.5.0 (GCM now compiled in, as on macOS), x86 and x86_64 builds compile the AVX2 kernels with `-mavx2 -mfma` |
| Branding | Sphere launcher icon like iOS/Mac (layered adaptive icon, themed monochrome, legacy and round), 5 alternate icons = iOS Nanogram designs (Comet, Night, Glass, Orbit, Speed), Nanogram notification and caller icons, intro = Sphere on a dark disc, "Nanogram" title and chat-list wordmark, ~50 strings that name the app (any language, cloud packs included) say Nanogram | Same identity as Nanogram iOS/Mac; no Telegram logo or app wording for our app. Network names (Premium, Stars, "anyone on Telegram") unchanged |
| minSdk | 31 (Android 12) instead of upstream's 23; prebuildApi 31 (NDK API level 31 sysroot, prebuild cache key changes once) | Owner decision 2026-11-14 (first 24, then 31): current Google libraries need 24, and 31 lets us use Android 12+ APIs (CallStyle, thermal headroom, ApplicationExitInfo, getLongVersionCode, hardware codec flags) without fallbacks. Devices on Android 7-11 get no updates (the updater skips builds whose minSdk is above the device). CPU baseline stays ARMv8.0 with run-time feature checks. Upstream `Build.VERSION.SDK_INT` checks are left as they are on purpose (no merge conflicts); only Nanogram-owned files drop sub-31 branches |
| Hardware codecs and automatic experiments | `NanogramMediaCapabilities` (performance class, hardware decoder/encoder lookup), `NanogramVideoDecoderSelector` in `VideoPlayer` (hardware video decoders first, software behind them, decoder fallback on), hardware-first encoder creation in the video converter, round-video recorder and `InstantCameraView`; Adaptive refresh rate is automatic on API 35+ and early GPU upload automatic on media performance class 31+ non-low-RAM phones (tri-state, testers can force either way, Back to automatic in Debug settings); GIF fast decode, Camera2 and system Telecom stay opt-in | Hardware codecs save battery and heat without changing what is sent (still H.264/AAC MP4); experiments only switch on by a signal that predicts the benefit |
| Clipboard | `NanogramClipboard.copyLink` flags private invite links as sensitive (`EXTRA_IS_SENSITIVE`, Android 13+); the three Copy link call sites call it instead of `setPrimaryClip` | Hides the link from the clipboard preview and overlay readers; one-line call-site changes keep upstream diffs small |
| Call notification | Ongoing and outgoing call notification uses `Notification.CallStyle.forOngoingCall` (upstream: plain builder with an End call action; only incoming used CallStyle) | System call chip and status-bar call indicator on Android 12+; the 'Leave' action label for group calls is the system's Hang up |
| Google sign-in (e-mail login) | Credential Manager "Sign in with Google" (`NanogramGoogleSignIn`, googleid 1.2.1) instead of the removed GoogleSignIn API | play-services-auth 22 removed GoogleSignIn |
| Diagnostics | Rolling quiet log in release builds (errors, warnings, key events; 5 MB, 3 days), own crash records, Settings > Send diagnostics: zip with device/power/network state, process exit history, ANR traces, logs; share sheet or Nanogram chat picker; verbose toggle | Testers are friends on their own phones and nobody on the team has an Android device; mirrors Nanogram iOS debug log export and MetricKit crash reports |
| Updates | GitHub releases instead of Telegram's server update call: manifest + APK from `klaipher/nanogram-android-releases`, SHA-256 and signer check, PackageInstaller; Settings row "Check for updates" | Our api_id gets no updates from Telegram; friends sideload the APK |
| Native LTO | ThinLTO on all C/C++ in release (upstream: full LTO on C files only, because voip/CMakeLists.txt resets the C++ flags) | Smaller and faster native code; parallel, cached release links |
| Native speed | `-O2` instead of `-Oz` for tgnet, sqlite and instead of `-Os` for the main library (set per source, as linked targets' PUBLIC -Os/-O3 would otherwise win); opus `-O2`; FFmpeg and libvpx built without `--enable-small`; libvpx arm64 with run-time dotprod/i8mm kernels | Message/database/frame paths are hot; size cost is small with ThinLTO and gc-sections |
| FFmpeg source | klaipher/FFmpeg `nanogram` (9.0.2 + 4 fixes), shared with iOS/macOS, instead of upstream FFmpeg + 2 local patches | One FFmpeg and one set of fixes for all Nanogram apps |
| Startup profiles | Baseline profile packed in the APK and written to ART by `androidx.profileinstaller` (compiled at the next background dexopt); R8 startup-profile dex layout; hand-written post-login rules and logged-in startup-prof.txt plus a generated logged-out profile (`:baselineprofile`, `ng profile`) | Sideloaded installs get no Play cloud profile, so ART would start without any profile |
| UI idle work | Shared 60 fps clock runs only while subscribed; no maximum-refresh-rate request on the main window after config changes or on long-lived PiP windows; light sensor released while paused; keyboard height and drafts saved with apply() | Fewer main-thread wakeups, lower panel refresh at rest, less battery, no fsync on the UI thread |
| Performance (core) | Log files opened off the main thread; `:widgets` engine only for recent widget users and released in the background; 250 ms throttle of `updateTimerProc`; no O_SYNC per download chunk, `synchronous=NORMAL` for cache4.db (power-loss durability below upstream FULL), files database in WAL, MP4 muxer and counters without per-write fsync; tgnet.dat writes coalesced; caches trimmed on `onTrimMemory`; MediaStore observers idle in the background; `sharing/` cleanup after 30 days | Battery, memory and flash wear without changing what users or the server see (docs/nanogram/performance.md) |
| Performance (media, db, search) | Save-to-gallery copies in 4 MB chunks; seek-bar preview reuses one decode bitmap; in-memory image cache 32-48 MB on average/high devices with enough RAM (upstream 30 MB cap); local dialog search with hash sets and cached transliteration. Debug-menu flags, default OFF: early GPU upload of decoded images, database tuning (8 MB page cache, 64 MB mmap on high-class 64-bit devices, prepared-statement cache; PRAGMA optimize was evaluated and dropped, no effect on SQLite 3.39.3), lighter H.264 decoding (no loop filter) for GIFs up to 320 px (384 px round videos not covered) | Smoother scrolling and scrubbing, less CPU on large copies and search; device-dependent items stay opt-in until measured (ANDROID-IO-1, VIDEO-2, IMG-1, IMG-2, DB-1, DB-2, SEARCH-1, SHARED-SQLITE-2, SHARED-FFMPEG-ANDROID-GIF-1) |
| System integration (Android) | Lite mode also follows system Battery Saver and severe thermal status; `localeConfig` for system App languages; dead permissions removed (legacy storage flag kept for Android 10), a switch for following Battery Saver and heat (global cleartext kept); diagnostics can record ProfilingManager system traces (opt-in, local); StrictMode thread/VM policies in debug builds; shared pool and inline path for link parsing; `apply()` instead of `commit()` on UI-thread preference writes. Experimental, off by default (`NanogramSystemFlags`): network state from the default NetworkCallback, Android 16 progress-centric notifications, system Photo Picker for "open in", charging skip for the power saver | Less battery and heat, fewer main-thread stalls, better Android 13+ integration, without changing what users or the server see |
| Startup flags (default off) | `StartupSettings.lazyAccountSlots` (unused account slots not constructed at start) and `skipPlayBillingAtStartup` (no Play Billing bind when `IS_BILLING_UNAVAILABLE`), stored in `mainconfig`; per-account package, signer and performance-class lookups cached; DNS config tasks on the DNS executor | No ConnectionsManager/FileLoader built for empty slots (receiver skips them), and no Play Billing bind, for single-account users; server-visible or purchase-flow impact, so off until checked on a build |
| R8 | `proguard-rules-tgnet-narrow.pro` prepared, not applied (upstream keeps all of `org.telegram.tgnet.**`) | Smaller dex and faster start once a release smoke test passes |
| QR, barcode and face detection | ML Kit (unbundled barcode scanning and face detection) instead of Mobile Vision `play-services-vision`; ZXing stays the QR fallback | Mobile Vision is retired; ML Kit is maintained |
| Adaptive refresh rate | Experiment (Debug settings, off): 60 fps content votes, no max-rate pin on overlay windows, fling velocity hints, API 35+ | Lower display power on LTPO panels; needs measuring before default-on |
| Camera2 capture | Experiment (Debug settings, off): `CameraView` uses Camera2Session with Camera1 fallback; video stabilization | Camera1 is deprecated; needs a device matrix before default-on |
| System call integration | Experiment (Debug settings, off): 1:1 calls registered with Telecom (transactional self-managed, API 34+) | Bluetooth/car/watch call controls and call priority; needs a device matrix |
| Performance experiments screen | Debug settings section with one switch per dark experiment (refresh rate, Telecom, Camera2, early GPU image upload, small-GIF decode, database tuning), device and SoC line, in-memory duration numbers, `performance-experiments.txt` in the diagnostics zip | Friends A/B-test the experiments on their own phones (mirrors the iOS Performance experiments section); durations only; numbers restart when a switch is flipped; frame numbers are collected only after the section was opened once |
| Round-video mini player | Close (x) button in the corner of the floating circle; the window is always removed when playback ends, the chat history is cleared or a hide animation is interrupted (upstream could leave a draggable window that could not be closed until restart) | Tester report: circle stuck on screen (TESTER-4) |
| Attach picker (gallery) | While the attach sheet is open, new photos are picked up 200 ms after the MediaStore change (upstream: 2 s); opening the sheet reloads at once if the gallery changed; resume check no longer misreads video counts | Tester report: photo taken right before attaching showed up late (TESTER-5) |
| Round video quality (Android) | On the legacy recorder only (V2, the 13.2.2 default, is already 480 px / 1.2 Mbps): circles are recorded at 480 px (server value if larger, up to 640) and 1.4-2 Mbps on average/high-class phones, from a larger camera stream, H.264 High/VBR when the encoder supports them (upstream: 384 px, 1 Mbps, Baseline defaults); trimmed circles keep that size; kill switch `round_quality_off` | Tester report: circles looked much worse than the camera app (TESTER-1) |
| Round video A/V sync (Android) | Camera and microphone timestamps put on one clock, audio aligned to the first video frame, audio stops with the video; kill switch `round_av_sync_off` | Tester report: sound ahead of the picture (TESTER-3) |
| Microphone choice | Settings row 'Microphone for voice messages and round videos': Automatic, phone, wired, USB, Bluetooth or LE Audio headset (upstream: built-in or classic Bluetooth SCO only, boolean); Bluetooth via communication device on Android 12+ | Tester report: no way to pick the microphone (TESTER-2) |
| tlottie source | Official dkaraush/tlottie v1.0.6 (92df98dc), the same pin as iOS and macOS, instead of klaipher/tlottie | One tlottie for all Nanogram apps; no local changes needed. Note: v1.0.6 drops the parse/render work budgets and raises memory caps (parse 13 -> 43.7 MB, render 36 MiB -> 116 MB at 720x720, scaled by area) |
| Rust toolchain | Pinned to 1.99.1 (`toolchain.properties` `rust`), the same channel Mac pins in core-xprojects/rust-toolchain.toml, for tlottie and wallet-engine prebuilts | One compiler for every Nanogram Rust library; tlottie floated on `stable`, wallet-engine was on its own 1.96.1 pin (wallet-engine on 1.99.1 is not built yet; if `ng prebuild` fails there, drop `RUSTUP_TOOLCHAIN` and keep only `TLOTTIE_RUST_TOOLCHAIN`) |
| Submodule urls | dav1d from code.videolan.org, wamr from bytecodealliance (same pins as before) | Canonical upstream homes, same as iOS/macOS |
| libyuv source | klaipher/libyuv `nanogram` (947f5326 = upstream 0b8dd231 minus the Bazel files), shared with iOS; macOS joins in the WebRTC step | One libyuv for all Nanogram apps; Android was on an older upstream commit (28ce69c2). `CAN_COMPILE_SME` stays FALSE |
| BoringSSL source | klaipher/boringssl `nanogram` (1c764cec = official 0.20261105.0 minus the Bazel package files), shared with iOS | One BoringSSL for both apps; iOS moved from its vendored 2ea3200c to the same release. Source files are byte-identical to the official tag, and the CMake build (`prebuild/build_boringssl.sh`) uses no deleted file. |
| OpenH264 source | klaipher/openh264 `nanogram` (v2.7.0 + H.264 level 6.0-6.2 + subcodec sprite mode, default off), shared with iOS/macOS | One OpenH264 for all Nanogram apps; the extra levels and sprite mode are inert unless a caller asks for them |
| rnnoise source | klaipher/rnnoise `nanogram` (xiph 0.2 + portability headers + denoise.c hardening + trimmed model) as submodule `jni/third_party/xiph/rnnoise`, shared with iOS/macOS; the 2018 in-tree copy `jni/voip/rnnoise` is gone | One rnnoise for all Nanogram apps. Chromium's rnnoise-vad (a different library, used by WebRTC's AGC2) comes from the WebRTC fork's `third_party/rnnoise` |
| libprisma source | klaipher/libprisma `nanogram` (Telegram 94640c63 + bounded tokenizing from iOS and Android + shared Apple glue), shared with iOS/macOS; the four override files and `generate.js` copy are gone; grammars.dat is generated with `PRISMA_JOIN_ALIASES=1` | One libprisma for all Nanogram apps; Android's regex-budget fixes now live in the shared source and iOS/macOS get them too |
| SQLite source | klaipher/sqlcipher-amalgamation `nanogram` (SQLCipher 4.20.0 on SQLite 3.54.1, iOS bytes) as submodule `jni/third_party/sqlite`; codec compiled in against BoringSSL, never keyed, so files stay plain SQLite; was pristine 3.39.3 in-tree | One SQLite for all Nanogram apps and a current engine (3.51.3+ WAL-reset fix); no encryption is applied on Android, only the shared source |
| wallet-engine source | klaipher/wallet-engine `nanogram` (iOS pin + Android key rotation, NFT transfer and TON Connect envelope; the recipient key is verified by default, Android passes `trust_recipient_public_key = false` by default through `WalletEngine2.TRUST_RECIPIENT_PUBLIC_KEY`, an explicit opt-in for a future confirmed key-rotation path); no patch file | One wallet engine for iOS and Android, same recipient-key check on both. Deviation from the old Android no-check send: a rotated recipient key now fails verification until the host sets the opt-in |
| twidget and widget-sandbox sources | klaipher/twidget and klaipher/widget-sandbox `nanogram` (Android's old pins + macOS commits + iOS litehtml edits and gumbo limits; nested quickjs = klaipher/quickjs `nanogram`), shared with iOS/macOS | One widget stack for all Nanogram apps; Android gains the iOS and macOS parser limits and fidelity fixes |
| Nested-filter depth in the widget painter | `WidgetSandboxPainter` draws at most 16 nested filters (`MAX_NESTED_FILTERS`); deeper FilterPush levels draw their content unfiltered, as widget-sandbox v0.6.5 asks (2,000 nested RenderNodes overflowed hwui's RenderThread stack). Upstream Telegram-Android's limit; drop ours when an upstream release carries it. |
