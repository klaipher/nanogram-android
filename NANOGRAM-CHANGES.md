# How Nanogram for Android differs from upstream Telegram for Android

Kept current with every change that alters behaviour or build compared with upstream (DrKLO/Telegram 13.2.2 (7303)).

| Area | Difference | Why |
|---|---|---|
| Repositories | Telegram-specific submodules point at klaipher forks; tgcalls shares `klaipher/tgcalls` with iOS/Mac (branch `nanogram-android`); media fork branch `nanogram-android` | Control over patches, one tgcalls fork for all apps |
| Identity | `org.klaipher.nanogram`, app name Nanogram, own api_id/api_hash via BuildConfig, own release key, own Firebase config only | Separate app; no Telegram credentials or Firebase project |
| Fork flags | `IS_BILLING_UNAVAILABLE = true`, `SUPPORTS_PASSKEYS = false`, empty Play Store URL | Play billing and passkeys only work for Telegram's app ids |
| ABIs | arm64-v8a only by default (`-PnanogramAbis=all` for all four) | Speed and size; like Apple-Silicon-only on the Mac |
| versionCode | minutes since 2020-01-01 of the build number × 10 + ABI digit | Every build updates the previous one; marketing version follows upstream |
| Toolchain | Gradle 9.9, AGP 9.5, Kotlin 2.4, NDK r30, CMake 4.1, compileSdk 37, Java 17 | Current toolchain; targetSdk 36 and minSdk 23 unchanged |
| Native build | ccache, no LTO in debug, prebuilts rebuilt from submodules into a cache, 16 KB flexible page sizes, uncompressed native libs | Build speed, disk, device storage, 16 KB-page devices |
| Native deps | FFmpeg 9.0.2 (n9.0.2, same as iOS and macOS); TDLib = iOS pin 0e88653d (1.8.69); abseil 20260817.0; BoringSSL 0.20261105.0; OpenH264 2.7.0; boost-regex 1.92.0 | Latest releases; one TDLib for iOS and Android |
| Gradle modules | 11 of 40 media modules; Huawei/HockeyApp/Standalone/test apps only with `-Pnanogram.allModules=true` | Configuration time |
| Biometrics | No FingerprintManager (removed from SDK 37): `androidx.biometric` 1.1.0 everywhere (FingerprintManagerCompat copy deleted); wallet uses the framework BiometricPrompt on R+ and AndroidX below; face/iris accepted where the device rates them Class 3 | Newer API on compileSdk 37, no stubs |
| WebRTC | `Candidate::set_type` without lifetimebound | NDK r30 clang rejects it (same as Mac tg_owt) |
| Branding | Sphere launcher icon like iOS/Mac (layered adaptive icon, themed monochrome, legacy and round), 5 alternate icons = iOS Nanogram designs (Comet, Night, Glass, Orbit, Speed), Nanogram notification and caller icons, intro = Sphere on a dark disc, "Nanogram" title and chat-list wordmark, ~50 strings that name the app (any language, cloud packs included) say Nanogram | Same identity as Nanogram iOS/Mac; no Telegram logo or app wording for our app. Network names (Premium, Stars, "anyone on Telegram") unchanged |
| minSdk | 24 (Android 7.0) instead of upstream's 23 | Owner decision 2026-11-14: current Google libraries (cast 23, maps 20.1, auth 22, webkit 1.18, palette 1.1, reCAPTCHA 18.9, Firebase BoM 35) need it |
| Google sign-in (e-mail login) | Credential Manager "Sign in with Google" (`NanogramGoogleSignIn`, googleid 1.2.1) instead of the removed GoogleSignIn API | play-services-auth 22 removed GoogleSignIn |
| Diagnostics | Rolling quiet log in release builds (errors, warnings, key events; 5 MB, 3 days), own crash records, Settings > Send diagnostics: zip with device/power/network state, process exit history, ANR traces, logs; share sheet or Nanogram chat picker; verbose toggle | Testers are friends on their own phones and nobody on the team has an Android device; mirrors Nanogram iOS debug log export and MetricKit crash reports |
| Updates | GitHub releases instead of Telegram's server update call: manifest + APK from `klaipher/nanogram-android-releases`, SHA-256 and signer check, PackageInstaller; Settings row "Check for updates" | Our api_id gets no updates from Telegram; friends sideload the APK |
| Native LTO | ThinLTO on all C/C++ in release (upstream: full LTO on C files only, because voip/CMakeLists.txt resets the C++ flags) | Smaller and faster native code; parallel, cached release links |
| Native speed | `-O2` instead of `-Oz` for tgnet, sqlite and instead of `-Os` for the main library (set per source, as linked targets' PUBLIC -Os/-O3 would otherwise win); opus `-O2`; FFmpeg and libvpx built without `--enable-small`; libvpx arm64 with run-time dotprod/i8mm kernels | Message/database/frame paths are hot; size cost is small with ThinLTO and gc-sections |
| FFmpeg source | klaipher/FFmpeg `nanogram` (9.0.2 + 4 fixes), shared with iOS/macOS, instead of upstream FFmpeg + 2 local patches | One FFmpeg and one set of fixes for all Nanogram apps |
| Startup profiles | Baseline profile packed in the APK and written to ART by `androidx.profileinstaller` (compiled at the next background dexopt); R8 startup-profile dex layout; hand-written post-login rules and logged-in startup-prof.txt plus a generated logged-out profile (`:baselineprofile`, `ng profile`) | Sideloaded installs get no Play cloud profile, so ART would start without any profile |
| UI idle work | Shared 60 fps clock runs only while subscribed; no maximum-refresh-rate request on the main window after config changes or on long-lived PiP windows; light sensor released while paused; keyboard height and drafts saved with apply() | Fewer main-thread wakeups, lower panel refresh at rest, less battery, no fsync on the UI thread |
| Performance (core) | Log files opened off the main thread; `:widgets` engine only for recent widget users and released in the background; 250 ms throttle of `updateTimerProc`; no O_SYNC per download chunk, `synchronous=NORMAL` for cache4.db (power-loss durability below upstream FULL), files database in WAL, MP4 muxer and counters without per-write fsync; tgnet.dat writes coalesced; caches trimmed on `onTrimMemory`; MediaStore observers idle in the background; `sharing/` cleanup after 30 days | Battery, memory and flash wear without changing what users or the server see (docs/nanogram/performance.md) |
| Performance (media, db, search) | Save-to-gallery copies in 4 MB chunks; seek-bar preview reuses one decode bitmap; in-memory image cache 32-48 MB on average/high devices with enough RAM (upstream 30 MB cap); local dialog search with hash sets and cached transliteration. Debug-menu flags, default OFF: early GPU upload of decoded images, database tuning (8 MB page cache, 64 MB mmap on high-class 64-bit devices, prepared-statement cache; PRAGMA optimize was evaluated and dropped, no effect on SQLite 3.39.3), lighter H.264 decoding (no loop filter) for GIFs up to 320 px (384 px round videos not covered) | Smoother scrolling and scrubbing, less CPU on large copies and search; device-dependent items stay opt-in until measured (ANDROID-IO-1, VIDEO-2, IMG-1, IMG-2, DB-1, DB-2, SEARCH-1, SHARED-SQLITE-2, SHARED-FFMPEG-ANDROID-GIF-1) |
| System integration (Android) | Lite mode also follows system Battery Saver and severe thermal status; `localeConfig` for system App languages; dead permissions removed (legacy storage flag kept for Android 10), a switch for following Battery Saver and heat (global cleartext kept); diagnostics can record ProfilingManager system traces (opt-in, local); StrictMode thread/VM policies in debug builds; shared pool and inline path for link parsing; `apply()` instead of `commit()` on UI-thread preference writes. Experimental, off by default (`NanogramSystemFlags`): network state from the default NetworkCallback, Android 16 progress-centric notifications, system Photo Picker for "open in", charging skip for the power saver | Less battery and heat, fewer main-thread stalls, better Android 13+ integration, without changing what users or the server see |
| Startup flags (default off) | `StartupSettings.lazyAccountSlots` (unused account slots not constructed at start) and `skipPlayBillingAtStartup` (no Play Billing bind when `IS_BILLING_UNAVAILABLE`), stored in `mainconfig`; per-account package, signer and performance-class lookups cached; DNS config tasks on the DNS executor | No ConnectionsManager/FileLoader built for empty slots (receiver skips them), and no Play Billing bind, for single-account users; server-visible or purchase-flow impact, so off until checked on a build |
| R8 | `proguard-rules-tgnet-narrow.pro` prepared, not applied (upstream keeps all of `org.telegram.tgnet.**`) | Smaller dex and faster start once a release smoke test passes |
| QR, barcode and face detection | ML Kit (unbundled barcode scanning and face detection) instead of Mobile Vision `play-services-vision`; ZXing stays the QR fallback | Mobile Vision is retired; ML Kit is maintained |
| Adaptive refresh rate | Experiment (Debug settings, off): 60 fps content votes, no max-rate pin on overlay windows, fling velocity hints, API 35+ | Lower display power on LTPO panels; needs measuring before default-on |
| Camera2 capture | Experiment (Debug settings, off): `CameraView` uses Camera2Session with Camera1 fallback; video stabilization | Camera1 is deprecated; needs a device matrix before default-on |
| System call integration | Experiment (Debug settings, off): 1:1 calls registered with Telecom (transactional self-managed, API 34+) | Bluetooth/car/watch call controls and call priority; needs a device matrix |
| Round-video mini player | Close (x) button in the corner of the floating circle; the window is always removed when playback ends, the chat history is cleared or a hide animation is interrupted (upstream could leave a draggable window that could not be closed until restart) | Tester report: circle stuck on screen (TESTER-4) |
| Attach picker (gallery) | While the attach sheet is open, new photos are picked up 200 ms after the MediaStore change (upstream: 2 s); opening the sheet reloads at once if the gallery changed; resume check no longer misreads video counts | Tester report: photo taken right before attaching showed up late (TESTER-5) |
